## 1. Quality Scores

| Metric | What it measures | Range | Pass guidance |
| --- | --- | --- | --- |
| `retrieval` | How relevant the retrieved chunks are to the question | `0.0-1.0` | Prefer `>= 0.70` |
| `faithfulness` | How well the answer stays grounded in retrieved context | `0.0-1.0` | Prefer `>= 0.70` |
| `answer_relevance` | How directly the answer addresses the user question | `0.0-1.0` | Prefer `>= 0.70` |
| `overall` | Combined quality signal used for pass/fail judgement | `0.0-1.0` | Typical pass threshold `>= 0.70` |
| `latency_ms` | End-to-end response time for one request | `>= 0` | Team-defined SLO |

## 2. Observability Metrics (Real /api/metrics Names)

| Real metric name | Type | Meaning | Typical alert trigger |
| --- | --- | --- | --- |
| `rag_chat_requests_total` | Counter | Number of chat API calls handled by this app process since start. If it was 120 and you send 3 requests, it becomes 123. | Sudden traffic spike/drop vs baseline |
| `rag_chat_errors_total` | Counter | Number of chat API calls that returned an error since start. If this grows faster than requests, reliability is degrading. | Error growth rate rising over window |
| `rag_chat_error_rate_percent` | Gauge | Current failure ratio in percent, computed from requests vs errors. Example: 8 errors out of 200 requests = 4%. | `> 5%` warning, `> 10%` critical |
| `rag_chat_latency_p50_ms` | Gauge | Current median response time in milliseconds. Half of requests are faster than this value. | Above expected baseline for sustained period |
| `rag_chat_latency_p95_ms` | Gauge | Current tail latency in milliseconds for typical slow users. 95 of 100 requests are faster than this number. | Above SLO for sustained period |
| `rag_chat_latency_p99_ms` | Gauge | Current extreme tail latency. Shows worst "normal" requests and catches timeout-like behavior. | Large jumps indicate tail instability |
| `rag_queries_pass_rate_percent` | Gauge | Percent of evaluated Q&A pairs marked as pass by the evaluation pipeline. Example: 67 pass out of 100 evaluated = 67%. | `< 70%` warning, `< 60%` critical |
| `rag_queries_failure_bad_retrieval` | Counter | How many evaluated queries failed because retrieved chunks were not relevant enough. | Rapid increase vs normal pattern |
| `rag_queries_failure_hallucination` | Counter | How many evaluated queries failed because the answer added claims not supported by retrieved context. | Any sustained upward trend |
| `rag_queries_failure_off_topic` | Counter | How many evaluated queries failed because answer intent drifted away from user question. | Significant increase after release |
| `rag_tokens_input_total` | Counter | Total prompt-side tokens consumed by this app process. Tracks prompt volume cost pressure. | Unusual jump without traffic increase |
| `rag_tokens_output_total` | Counter | Total completion-side tokens generated by this app process. Tracks answer verbosity and cost pressure. | Output/input ratio drifting upward |

## 3. Tuning Knobs

| Knob | What it changes | Safe starting point | Change when |
| --- | --- | --- | --- |
| `top_k` | Number of retrieved chunks | `3-5` | Context misses key facts |
| `RAG_CHUNK_SIZE` | Chunk size during ingestion | `500-1000` chars | Answers need broader context |
| `RAG_CHUNK_OVERLAP` | Overlap between adjacent chunks | `50-150` chars | Important text is split at boundaries |
| `RERANKER_ENABLED` | Secondary relevance ranking step | `false` | Retrieval has near-miss chunks |
| `HYBRID_SEARCH_ENABLED` | Semantic + keyword retrieval | `false` | IDs/keywords are critical |
| `HYBRID_ALPHA` | Semantic vs keyword weighting | `0.7` | Need to rebalance semantic vs lexical |
| `HNSW_M` | Graph connectivity in HNSW index | provider default | Recall is weak at scale |
| `HNSW_EF_SEARCH` | Search depth at query time | provider default | Need higher recall on hard queries |

## 4. Evaluation Modes

| Mode | What it does | Use for |
| --- | --- | --- |
| `rule_based` | Heuristic scoring from overlap signals | Fast local checks |
| `llm_judge` | LLM rubric scoring | Semantic quality checks |
| `combined` | Both lanes on the same result page | Default for lab comparisons |

## 5. Score Interpretation Bands

| Band | Interpretation | Default action |
| --- | --- | --- |
| `>= 0.85` | Strong | Keep as baseline |
| `0.70-0.84` | Usable | Improve if high-priority path |
| `0.50-0.69` | Weak | Investigate promptly |
| `< 0.50` | Poor | Treat as failing quality |

## 7. Formula Cheatsheet

| Metric | Formula |
| --- | --- |
| `rag_chat_error_rate_percent` | `(rag_chat_errors_total / rag_chat_requests_total) * 100` |
| `rag_queries_pass_rate_percent` | `(passed_queries / total_queries) * 100` |
| `rag_chat_latency_p95_ms` | 95th percentile of collected `latency_ms` samples |
